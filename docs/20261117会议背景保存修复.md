# 会议背景保存修复

修复分支：`codex/summary-templates-layout-20261107`。

## 原因

转写面板底部的会议背景输入框此前只更新页面状态，没有保存按钮和失焦保存。只有点击上方“保存会议设置”，或生成纪要时才会写入数据库。保存错误只在上方设置区显示，底部输入框没有提示。

## 修改

- 底部增加“保存会议背景”按钮及加载、未保存、保存中、已保存、失败状态。
- 离开背景输入框时自动保存到本次会议；上方会议背景输入框也采用相同方式。
- 会议设置加载或保存期间禁用背景输入，避免读取覆盖输入或产生不明确的保存状态。
- 保存失败保留输入与未保存状态，直接在底部展示具体错误，可修正后重试。
- 失焦和紧接着点击保存或生成纪要时，相同的在途请求复用；不同版本按顺序写入，避免旧请求覆盖新内容。
- 切换会议或离开页面时，已发起的保存仍写入原会议，不把旧会议内容用于新会议，也不继续从旧页面启动生成。

背景与出席人员、缺席人员、主持人和模板共同保存在本次会议设置中。若出席、缺席名单冲突等校验不通过，需要先修正提示的内容。背景保存不会自动生成纪要、创建 Lark 任务或向群发送消息。

## 使用

填写后点击其他位置，或点击“保存会议背景”，确认状态变为“已保存”再关闭软件。直接强制结束进程、断电等情形不能保证正在输入但尚未触发保存的文字已经写入。

本次通过 28 项相关前端测试，覆盖保存与重新读取、会议隔离、并发保存顺序、失败重试、离开页面后的原会议写入及纪要生成快照。安装包包含此前的行动项同步、知识库整库目录选择等分支改动。本轮未自动安装，也未修改用户真实会议背景或向 Lark 发送数据。

# 多人共用会议助手，各自电脑录音

## 本次改动

- 不部署统一服务。每台 Meetily 用自己登录的 Lark 用户凭证读取所选群消息，不再建立机器人事件长连接，避免多个客户端竞争同一条事件。
- 可选择本人和机器人都已加入的群，最多十个。保存选择后开始监听，首次启用不补执行旧指令。
- 群里实际 @会议助手并发送九位会议号、视频会议入会链接或完整邀请，即刻建立六小时有效的待参会绑定，不等待邀请里的开始时间。
- 只有指令发送者登录的那台电脑发一次即时回执，其他成员电脑只建立自己的本地绑定。发送者未开启软件或没有同步该群时，没有回执，但其他符合条件的客户端仍可读取并绑定。
- 移除预约创建、定时提醒和预约重试入口；升级会取消旧待提醒任务并解除旧待参会绑定，需要重新发指令。
- 本人账号进入指定会议后，本机录制麦克风与系统声音；确认离会后停止，沿用离会补齐转写、生成纪要流程。手动停止后同一个会议实例不再自动启动。
- 不下载云录音。各电脑的音频、转写和纪要分别保存在本机。云文档保存、群消息、附件和行动项继续由用户审核确认。

## 首次配置

1. 管理员为同一个 Lark 自建应用发布下列权限，并把会议助手加入目标群。
2. 每台电脑安装本次 Windows 包，使用现有“后台辅助导入”配置相同应用凭证。凭证在 Windows 当前用户环境下加密保存，登录不会自动取得应用密钥。无需另建机器人，无需统一服务器。
3. 设置 → Lark 机器人 → 选择“同步群会议 · 本机自动录音（多人共用助手）”，启用助手并保存。
4. 点击“授权会议助手”，每人登录自己的账号。老用户也需要重新授权一次，以取得新增的用户身份群消息权限。
5. 点击“加载我的群”，选择会议群，勾选“本人加入已同步的指定会议后，自动在本机录音”，再次保存。
6. 提前选好转写模型、纪要模型、麦克风和系统声音设备；群里实际 @机器人后发送 `会议ID:550 544 175`，再在这台电脑加入该会议。
7. 看到 Meetily 开始录音提示后再正式讨论，离会后检查转写和纪要，确认后再发送。

更换登录账号会清空群选择，需要重新选择本人会议群。群同步开关与自动录音开关分别控制；自动录音未开启时，群指令不会偷偷打开麦克风，之后开启也不会追溯执行旧指令。

## Lark 权限

应用后台使用国际版 Lark：<https://open.larksuite.com/app>。开通后还要完成版本发布或审批，随后在 Meetily 重新授权。

| 身份 | 权限 | 用途 |
| --- | --- | --- |
| 用户 | `im:chat:read` | 获取本人所在群 |
| 用户 | `im:message:readonly` | 读取消息基础权限 |
| 用户 | `im:message.group_msg:get_as_user` | 以本人身份读取所选群的历史消息 |
| 用户 | `vc:meeting.meetingevent:read` | 查询本人当前参会状态，沿用原有实现 |
| 用户 | `vc:meeting` | 沿用原会议授权范围 |
| 用户 | `calendar:calendar.event:read` | 核对完整日程分享邀请；直接会议号不依赖日程匹配 |
| 用户 | `offline_access` | 支持自动续期 |
| 应用 | `im:chat:read` | 获取机器人所在群，与本人群列表取交集 |
| 应用 | `im:message:send_as_bot` | 发送即时指令回执及人工确认的纪要 |

应用需开启机器人能力。授权回调地址为 `http://127.0.0.1:18576/lark/callback`，由各自电脑接收，不是统一服务。机器人消息接收事件和长连接不再是本流程的依赖；已有后台订阅可以保留，但请退出所有旧版 Meetily 接收实例，避免旧版继续处理指令或提醒。

不同租户可能存在权限开放范围或审批限制。本次代码不代表上述权限已在租户中获批。无法读取时会显示错误，绝不退回应用身份读取所有群来绕过本人账号权限。

## 指令和边界

- `@会议助手 会议ID:550 544 175`、`会议 ID：550 544 175` 以及 Lark 官方 `/j/550544175` 入会链接均支持；必须使用真正的 @提及。
- 支持完整视频会议邀请。完整日程分享邀请需能从本人主日历唯一核对到同一分享链接及会议号，不能访问时请改发九位会议号或入会链接。
- 只同步保存群选择之后、最近十分钟内的新指令。电脑离线超过十分钟再启动，请重新发指令。不会重放几天前的群消息。
- 同一条消息按应用、账号、消息 ID 在本机持久去重。回执带稳定幂等标识；结果不确定时保留绑定、不自动重发，在设置的“最近群指令”中提示核对。
- 同一账号应只在一台电脑开启自动录音。没有共享服务，本地去重记录不能提供跨电脑永久的严格一次执行保证。
- 读取的是账号参会状态，无法区别同一个账号在手机或另一台电脑加入会议。因此请在运行 Meetily 的电脑参会；不要用此模式监听自己在其他设备上的会议。
- 重复发送已在录制的会议号不会中断或重开录音。离会后下一场复用该号码时需重新发指令。多个群绑定同一场会议时不自动选择群，请手动录音并选群。
- 发送者的即时回执表示其电脑已经处理指令，不代表每个同事的电脑均已同步或成功录音；每人以自己 Meetily 的提示为准。
- 撤回指令不是撤销录音操作：已读取的绑定需在各自设置中移除，已开始的录音可手动停止。

## 延迟、调用量与失败处理

正常情况下每十五秒查询每个所选群；有待参会绑定或正在录音时，每五秒查询一次本人会议状态。绑定后入会仍有数秒检测延迟，群同步尚未完成就入会可能等待更久，无法补录这些声音。

单群空闲同步约每小时 240 次请求；待参会或录音时会议状态查询约每小时 720 次，翻页、登录续期、回执等另计。多群、多人共享应用会累加额度，需要按公司实际套餐核对 Lark 限额。无有效待参会绑定且没有录音时不会持续查询本人参会状态。

群查询失败按三十秒到五分钟逐步退避；会议状态查询失败缓存一分钟，避免连续请求。分页读取按固定时间窗口续读，缺少列表或分页信息时保留进度，不将失败当成“无消息”。状态不明确时不猜测会议身份，也不下载云录音兜底。

## 验证范围

本次包含前端配置交互测试、两份独立本地数据库模拟两名同事、消息身份与时间过滤、发送者独占回执、重复消息去重、不确定回执不重试、切换账号与移除群、分页续读和旧预约迁移验证。

自动化测试不会真实发送 Lark 消息或启动麦克风。还需用两名同事的真实账号完成租户权限、跨账号群同步、实际入会和双方声音录制验收。安装包交付不等于这些真人场景已经验收。

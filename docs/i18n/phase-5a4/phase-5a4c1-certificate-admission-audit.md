## 3. 新增和强化的控制

### 3.1 受控准入记录

`windows-certificate-admission.v1.json` 冻结以下内容：

- 目标签名策略和 `productionActive` 集合；
- 精确主体、SHA-1 指纹、序列号、颁发者和有效期公开字段；
- 代码签名 EKU `1.3.6.1.5.5.7.3.3`；
- 至少 30 天剩余有效期；
- 可信证书链、禁止自签名、禁止历史指纹复用；
- DigiCert 健康检查和证书同步；
- 一次性 PE 副本真实持钥证明；
- Tauri 更新私钥和密码入口存在性；
- 发布负责人和安全复核人两项独立、带时间和可追踪引用的批准；
- 明确规定“证书批准不等于发布批准”，后续仍必须执行真实签名 RC 门禁。

### 3.2 证书准入模块

`Meetily.CertificateAdmission.psm1` 提供：

- 准入 JSON 的强类型约束读取；
- 只输出环境变量存在性布尔值的脱敏审计；
- 从 Tauri minisign 公钥解析并核对 Key ID；
- Windows 证书公开证据采集；
- 在线撤销模式的 X.509 链构建；
- 准入记录、证书公开证据和完整就绪状态三层验证；
- 唯一活动指纹、双审批、主体、指纹、序列号、颁发者、EKU、有效期和历史证书隔离检查。

### 3.3 真实预审脚本

`audit-phase5a4c1-certificate-admission.ps1` 默认只执行非破坏性本机预审；仅在显式指定 `-RunDigiCertConnectivity` 时调用健康检查和证书同步；仅在同时提供一次性证明输入并满足前置条件时，复制到受控临时目录后调用 `smctl sign --tool=signtool --timestamp=true`。DigiCert 输出被抑制，临时目录路径必须具有固定安全前缀才能递归删除。

报告只包含：

- 环境入口是否存在；
- 工具是否存在；
- 健康检查和同步是否执行／通过；
- 证书公开字段和链状态；
- 持钥证明的公开签名证据；
- 准入失败原因。

报告不包含 API Key、P12 密码、Keypair Alias 值、Tauri 私钥、私钥密码或客户端证书路径。

### 3.4 生产前置门禁接入

`prepare-digicert-signing.ps1` 现在首先读取准入记录。状态不是 `Approved`、两项审批不完整、候选证书不等于唯一 `productionActive` 指纹或使用历史指纹时，在调用 DigiCert 前立即失败。证书同步后还要执行准入公开证据验证，不能仅依赖环境变量和 `smctl healthcheck`。

5A-4C-1 的准入机制和失败关闭实现可验收，但真实生产证书尚未准入。不得把 `PendingCandidateEvidence` 改写为完成，也不得用自签名证书、上游历史证书或合成证据替代。

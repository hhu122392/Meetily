# Meetily 中文化发布回滚操作手册

## 1. 目标与原则

本手册用于中文化发布后出现启动、录音、保存、语言资源或隐私问题时，安全停止扩大分发并恢复英文或上一版本。任何回滚都必须优先保护会议数据库、录音文件、自定义模板和模型文件。

禁止直接删除 `%APPDATA%`、用户录音目录或共享模板仓储。禁止使用未解析的环境变量、通配符或递归删除命令处理用户数据。

## 2. 触发条件

发生以下任一事件立即停止扩大分发：

- Locale 切换导致会议、录音、转录或摘要数据丢失；
- 中文化导致录音无法停止或文件无法保存；
- 中文资源损坏导致应用无法启动且英文回退失效；
- 录音同意、隐私或分析授权文案存在实质性错误；
- 新版本泄露 API Key、绝对路径、堆栈或会议内容；
- 中文核心流程失败率显著高于英文基线；
- 安装、升级或卸载破坏用户数据。

## 3. 回滚前取证和升级备份

1. 记录应用版本、安装包 SHA-256、操作系统、Locale、错误码和发生时间。
2. 退出 Meetily；在任务管理器确认没有正在保存的录音或转录任务。
3. 只读确认下列位置的实际路径和大小：
   - Tauri 应用数据目录：由应用 `app_data_dir` 返回，Windows 通常位于 `%APPDATA%\<bundle-id>`；
   - 自定义模板：`%APPDATA%\Meetily\templates`；
   - 用户选择的录音目录：以应用设置显示的绝对路径为准；
   - 模型目录：应用数据目录下的 `models`；
   - 数据库：应用数据目录下的 `meeting_minutes.sqlite` 及可能存在的 `-wal`、`-shm`。
4. Windows NSIS 安装程序在升级覆盖程序文件之前，会自动停止 Meetily，并对整个应用数据目录建立版本化备份。备份位于应用数据目录的同级目录：`%APPDATA%\<bundle-id>.rollback-backups`。
5. 升级安装成功前，必须确认 `last-upgrade-backup-result.json` 的 `status` 为 `PASS`，其中源版本、目标版本、文件数、总字节数和清单 SHA-256 均有值。自动备份失败时，安装程序会在复制新版程序文件前退出，不能强行继续升级。
6. 备份目录内的 `backup-manifest.json` 记录每个文件的相对路径、大小和 SHA-256。恢复工具会同时核对版本、目录身份、文件数量、总字节数和全部文件散列；不要手工改清单。
7. 不要在数据库仍有 `-wal` 活动写入时只复制主数据库文件，也不要只备份 `meeting_minutes.sqlite`。支持回退使用安装程序生成的完整应用数据快照。

## 4. 优先级一：运行时英文回退

如果应用仍能启动且故障仅影响中文显示：

1. 设置 → 界面语言 → English；
2. 验证 `<html lang="en">`、托盘、通知和模板列表均为英文；
3. 验证转录语言、摘要语言、模型、录音目录和当前会议未改变；
4. 重启应用并确认英文设置持久化；
5. 暂停中文分发，保留当前版本供英文用户继续使用。

若语言包加载失败，应用应自动回退英文；如果无法回退并阻止启动，直接进入版本回滚。

## 5. 优先级二：版本回滚

Windows 直接覆盖安装更低版本会被明确拒绝，安装程序退出码为 `3`。这条保护不能绕过，因为新版数据库可能已经写入旧版程序不认识的迁移。直接运行旧安装包不会自动把数据库变回旧结构。

支持的回退固定按下面顺序执行：

1. 获取上一批准版本的安装包、SHA-256 和签名验证结果；禁止使用来源不明的二进制。
2. 关闭 Meetily，确认没有录音、转写、摘要或数据库写入进程。
3. 找到升级时生成的 `last-upgrade-backup-result.json`，读取其中唯一的 `result.backup_directory`。确认 `result.source_version` 等于要恢复的旧版本，`result.target_version` 等于当前版本。
4. 使用备份根目录内自带的可信工具先执行校验。下面四个路径和两个版本都必须替换成已核对的准确值，不允许使用通配符：

   ```powershell
   powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass `
     -File '<备份根目录>\tools\meetily-versioned-data.ps1' `
     -Mode Verify `
     -DataRoot '<当前应用数据目录>' `
     -BackupRoot '<备份根目录>' `
     -BackupDirectory '<last-upgrade-backup-result.json 中的 backup_directory>' `
     -SourceVersion '<上一批准版本>' `
     -TargetVersion '<当前版本>' `
     -ResultPath '<备份根目录>\last-verify-result.json'
   ```

5. 校验命令退出码必须为 `0`，`last-verify-result.json` 的 `status` 必须为 `PASS`。任一版本或散列不匹配时停止回退，不能手工删迁移记录、改数据库版本或忽略错误。
6. 正常卸载当前程序并保留应用数据。不要选择删除应用数据。
7. 使用同一工具、同一备份目录和同一版本号执行原子恢复：

   ```powershell
   powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass `
     -File '<备份根目录>\tools\meetily-versioned-data.ps1' `
     -Mode Restore `
     -DataRoot '<当前应用数据目录>' `
     -BackupRoot '<备份根目录>' `
     -BackupDirectory '<已验证的 backup_directory>' `
     -SourceVersion '<上一批准版本>' `
     -TargetVersion '<当前版本>' `
     -ResultPath '<备份根目录>\last-restore-result.json'
   ```

8. 恢复命令退出码必须为 `0`，`last-restore-result.json` 的 `status` 必须为 `PASS`。恢复过程先在同一磁盘准备并校验完整副本，再替换应用数据目录。被替换的当前版本数据会保存到备份根目录的 `recovery` 子目录，不会直接删除。
9. 安装上一批准版本。启动后至少稳定运行 30 秒，并依次验证会议列表、保护会议、人工转写标记、录音目录、模型列表、自定义模板和英文核心流程。
10. 对回退前基线和回退后数据执行数据库完整性、会议数、转写数、人工修改标记、关键设置和模板 SHA-256 核对。全部一致后才宣布回退成功。

## 6. 恢复失败时怎么处理

- 版本不符、清单损坏、文件大小不符或 SHA-256 不符时，工具会在替换前拒绝恢复，当前数据保持不变。
- 替换过程中发生错误时，工具会把原数据放回原位置；失败的临时副本会保存在备份根目录的 `failed-restores` 子目录用于排查。
- 不要删除 `recovery`、`failed-restores`、备份清单或失败结果。先记录错误、退出码和相关文件 SHA-256，再由发布负责人处理。
- 恢复失败后禁止继续安装旧版本。必须先确认当前数据已经恢复到执行前的散列，或从另一个已经验证的完整备份重新开始。
- 禁止直接删除迁移记录、降低数据库版本号、只替换主数据库文件或让旧程序带着迁移错误启动。

## 7. 回滚后验收

- 应用可启动；
- 英文 UI、托盘和通知可用；
- 会议和录音数量未减少；
- 随机旧会议可打开；
- 新旧自定义模板可读取；
- 录音可开始、停止并保存；
- 未知配置键不会导致崩溃；
- 没有 Secret、路径或会议内容泄露；
- 记录最终版本、安装包哈希、数据核对结果和批准人。

| 安全／隐私负责人 | 评估泄露和文案风险 | OPEN |

## 使用流程

1. 打开历史会议，在转写工具栏选择“优化转写”，再选择“转写文字纠错”。
2. 首先展示术语规则候选，此步骤不应用纠错。
3. 可选择已配置的本地或 API 模型执行 AI 校对；仅由用户点击时请求模型，不自动发送转写内容做校对。
4. 核对原文与建议，勾选后应用；重叠候选不能同时应用，原文已变化时拒绝写回。
5. 应用前自动备份；应用后显示差异，用户保留结果或再次确认恢复备份。已有纪要不会自动变化，需要时重新生成。
6. 数据库已写入但文件同步失败时显示提示，可重试；待同步状态保存在当前公司数据库，重启后仍可恢复。

## 定制版适配

- 所有会议读写限定当前公司数据库，并核对数据库录音目录与请求目录的规范化路径一致。
- 校对模型偏好保存于当前公司资料目录；模型调用继续使用当前版本的供应商、密钥和本地模型实现。
- 纠错、恢复及模型调用持有录音存储使用锁，防止处理中切换公司或迁移目录。
- 纠错与后台重新转写的数据库、文件写入共用互斥锁；后台写入前会完成此前待同步内容。
- 录音目录迁移时同步更新待同步文件记录的目录。
- 原有迁移文件保持不变，待同步表通过幂等建表按需初始化。
- 中英文文案沿用主线相关词条，接入当前轻量语言机制。

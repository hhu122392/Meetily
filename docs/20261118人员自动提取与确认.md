# 人员自动提取、常用名单与发送确认

## 自动回填

打开会议详情、开始生成纪要、打开 Lark 选群发送窗口时，从本场转写原文提取明确的出席与缺席表述。示例包括“出席人员：张三、李四”“缺席人员 Mike”“张三今天请假”“李四和王五已到场”。不需要云录音，也不会增加模型调用。

本轮采用保守的本地文本规则，不是声纹身份识别，也不能保证理解所有口语表达。未明确提到、历史或未来会议、假设、问句、前后冲突的人员不自动填入。识别依据可以展开查看；未识别到不等于没有出席或缺席人员。主持人仍由用户填写。

已自动填入的名单会随原文变化更新；手动修改和手动清空按字段保护，不被再次识别覆盖。旧版本已填写的名单按手动名单保留。姓名拼写以转写结果为准，需核对同音字。

## 常用名单

按当前公司和纪要模板保存候选人员，不代表实际出席。列表中逐人选择“出席 / 缺席 / 待确认”，只调整选中的人员，其他已填写人员不被整批替换。待确认者不自动列为缺席。

可直接编辑并保存常用名单，或显式将本场出席与缺席的合集存为常用名单。本场调整不会自动覆盖常用名单。常用姓名也提供给现有转写纠错流程作为参考，不作确定性同音替换。

## 发送确认

Lark 选群发送默认带入本场已识别或手动保存的名单。用户必须勾选“我已核对出席、缺席名单”后才能预览，修改名单会清除确认与旧预览。未明确提到的人允许保持空白，不要求补全常用名单。

在发送窗口修改的出席与缺席名单，会在点击预览时保存到本场会议；不会重写已保存的云文档正文。实际发送仍需单独确认。旧版未确认人员的发送预览会被阻止，需重新预览。

本次继续包含目录自动加载、已保存云空间与知识库两篇纪要链接多选功能；不新增 Lark API 权限。

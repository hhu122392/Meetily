# Lark 日程创建与会议分享设计

状态：早期创建日程方案。用户已选择「Lark 创建周期日程 → Meetily 同步 → 本地录音 → 会后手动选群发纪要」，当前实现及操作见 [周期日程本地录音](LARK_CALENDAR_LOCAL_ZH.md)。本文件中 Meetily 创建、修改、取消日程的内容保留为后续设计，不属于本轮实现。

## 使用流程

选择模板和项目 → 填写时间及重复规则 → 核对邀请人员、目标群 → 创建日程并分享 → 从本次日程手动开始本地录音 → 核对出席情况 → 生成并发送本次纪要。

日程由当前登录用户创建，群通知由会议助手发送。首次连接个人日历时单独申请日历权限，不启用云录音或机器人开会事件。应用凭证辅助导入与个人日历授权是两个步骤，普通账号登录不会自动获得应用密钥。

## 创建表单

默认显示模板/项目、会议名称、首次开始时间、时长、重复、邀请人员和分享群。议程及其他设置折叠。底部为「保存草稿」「创建日程并分享」。

重复选项：不重复、每天、每周、每两周、每月、自定义。选择每周可选多个星期；每月可按日期或第几个星期几，例如每月第一个周一。自定义支持每隔若干天、周、月。

结束条件：永不结束、指定日期、重复若干次。默认北京时间，显示完整规则和接下来三次日期供核对；结束日期包含当日符合规则的实例。每月日期不存在时跳过该月，并在规则旁说明。周一至周五不等同于中国法定工作日，第一版不自动识别调休和节假日，可取消单次会议。

模板带入常用邀请人员、项目和目标群，均可修改。姓名需先绑定到明确的 Lark 用户身份；不能按姓名猜测账号。分享群不等于邀请整个群，第一版默认只邀请选中的人员。

## 周期系列与每次会议

一个周期系列保存共同规则、默认人员、项目、模板和默认分享群；每次会议单独保存实际时间、录音、出席/缺席、纪要、归档文档和发送记录。

用 Lark 日历及系列标识、实例原始起始时间关联每次会议，保留远端实例标识。不能只用会议号或调整后的开始时间区分实例；同一系列可以共用会议号，某次也可能被改期。

首页显示最近待开会议，每次均提供「加入会议」「开始本地录音」。实际录音起止与计划时间分开记录。邀请状态和接受邀请状态不能作为实际出席证据，出席情况会后由用户确认。

项目归档按「项目 / 系列」组织，每次创建独立文档，标题包含本次会议日期。不得把系列所有录音和纪要合成同一份，也不得用最新一次覆盖历史纪要。

## 改期和取消

编辑或取消时必须明确选择「仅本次」「本次及以后」「整个系列」，默认仅本次。页面显示影响范围和最近受影响日期，再提交。

改动未来邀请人员、模板、项目等默认配置不能重写已生成的历史录音和纪要。取消日历日程不删除本地历史记录。整个系列取消与结束未来重复区分展示。

「本次及以后」涉及系列截断、新系列创建和例外实例迁移，不能假设远端有单一原子操作。实现前按当前 Lark API 能力核验；逐步保存处理状态，失败后恢复，不重复创建。迁移保留已经改期、取消的实例含义及本地关联。

## 分享、提醒和同步

首次分享显示周期规则、下一次时间、发起人、议程和日程/入会链接。提供手动「分享本次会议」；改期或取消后明确选择通知原群。群消息只作为通知，最新时间以日程为准。

每次会议提醒交给 Lark 日历。无公司服务器时不承诺电脑关闭后仍由 Meetily 定时发群；第一版不做每周定时机器人群提醒。

创建日程、邀请人员、分享群卡片分别记录状态。邀请或分享失败时只补做失败步骤，不重建日程。创建请求使用防重复标识；结果不明确时先查询核对，不盲目重试。

打开 Meetily、刷新待开列表、开始录音前读取日程最新状态，识别用户在 Lark 中直接改期或取消的情况。离线显示上次同步时间，不将缓存标为最新。无需集中事件接收主机。

## 第一版验收

- 每周、隔周、每月和结束条件正确，含跨月、跨年、月末缺失日期；北京时间显示一致。
- 仅改本次不影响下次，修改本次及以后不改变历史；取消后不再提示该次开会。
- 系列内两次会议即使会议号相同，录音、纪要、人员和发送记录仍独立。
- 同事分别用个人账号创建，日历归属正确；没有权限时显示缺失能力，不静默换成其他身份。
- 创建成功但邀请或分享失败时可恢复，双击和重启不重复创建；改期/取消部分失败可继续处理。
- 实际会议不依赖云录音，自动录制设置关闭情况需真实租户核验；双向音频需通话实测。
- 实现需新增日历权限并核验当前应用授权，不把 Lark 客户端支持的操作直接当作 API 已验证通过。

# 纪要模板规则与导入

入口：设置 → 纪要 → 管理纪要模板 → 导入 JSON。提供两个可直接导入的例子：

- [项目例会-v2.json](示例/项目例会-v2.json)：摘要、出席/缺席人员、决策和行动项表格。
- [仅摘要-v2.json](示例/仅摘要-v2.json)：只输出摘要，用于验证没有行动项栏目时，程序仍独立提取行动项。

每次导入会创建新的自定义模板，不覆盖同名模板。内置模板先复制再编辑。可以设为当前公司的默认模板，也可以在某场会议中单独选择；不会自动改写历史纪要。

## v2 格式

顶层使用 `schema_version: 2`，包含 `id`、`name`、`description`、`version`、`locale`、`tags`、`source`、`created_at`、`updated_at`、`sections` 和可选 `extensions`。示例采用 `source: {"type":"manual"}`；导入时程序自动记录来源，不需伪造文件哈希。时间用 RFC3339 格式。

单文件不得超过 800,000 字节，栏目数量为 1～50。栏目 `id` 使用小写英文字母、数字、下划线或连字符，且不得重复；标题也不能重复。`format` 只接受 `paragraph`、`list` 或 `string`，不接受 `table`。需要表格时，在 `instruction`、`item_format` 中明确 Markdown 表头和空单元格规则，参考项目例会示例。

`required` 决定栏目是否必需。`empty_behavior` 只接受 `omit`、`show_not_mentioned`；省略空栏目时使用 `required:false` 配合 `omit`。栏目说明最长 10,000 字，名称和标题等字段也有长度限制，导入报错时按具体字段修正。不要添加任意顶层字段；扩展数据放在 `extensions`。

`locale` 是模板信息，实际纪要语言由会议/全局语言设置决定。程序生成会议标题，不需要再增加重复的“标题”栏目。模板是指导模型的结构规则，不是保证模型逐字按格式输出的固定渲染器；重要纪要需人工核对。

## 人员和行动项

程序从明确的参会、缺席表述提取人员，保留手动修改；名单不等于实际出席，被提到或被分配任务也不等于出席。未明确提到的留空，不应通过常用名单减法猜测缺席。

生成纪要时默认独立提取会议明确确认、尚待完成的行动项。模板带有相应栏目时才写入正文；没有相应栏目仍可在行动项面板查看。负责人、截止时间未提到时留空，默认不勾选同步；相对日期由本人确认具体日期，负责人通过群成员匹配，不自动选择当前登录者。

行动项提取最多自动尝试两次；失败不阻止纪要生成，界面保留警告。可重新生成纪要重试或手工补充。原文依据由程序维护，人工可编辑事项及确认字段，但不能改写依据。纪要正文与行动项草稿分别保存；修改正文中的行动项表格不等于修改独立草稿，同步前须在行动项面板核对。长依据同步到 Lark 时，任务描述附前 2,000 字并注明节选，完整原文仍保存在 Meetily，预览中会提示。

任务描述的长度限制依据 [Lark 官方 SDK 的任务字段定义](https://github.com/larksuite/oapi-sdk-go/blob/v3_main/service/task/v2/model.go)。完整依据保存在本地草稿，不会因发送节选而被截断。

## 推荐试用步骤

导入项目例会模板，设为默认或在测试会议中选择。用包含“出席人员：张三、李四。王五今天请假。确定补充接口测试，负责人李四。”的测试转写生成纪要，核对名单、任务及空截止时间。示例人名仅是测试材料，不是默认人员。

随后切换仅摘要模板重新生成：正文应只有摘要，行动项仍可单独核对。两种模板都不会自动向群发送纪要或自动创建 Lark 任务。

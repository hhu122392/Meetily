# Windows 与 Mac 安装

## 选择安装包

| 电脑 | 文件 |
| --- | --- |
| Windows x64 | 名称包含 Windows-x64 的 setup.exe |
| Apple Silicon Mac（M 系列） | 名称包含 Mac-AppleSilicon 的 dmg |
| Intel Mac | 名称包含 Mac-Intel 的 dmg |

Mac 定制配置最低系统版本为 macOS 14.4。Windows 包使用 CPU 推理；Mac 构建启用 Metal。模型效果和速度还取决于模型、内存、录音和设备，不能按安装包大小推断模型是否已下载。

安装前核对发布目录中的源码提交、文件大小和 SHA256，不混用旧包。Windows 可运行 `Get-FileHash -Algorithm SHA256 -LiteralPath '安装包完整路径'`；Mac 可运行 `shasum -a 256 '安装包完整路径'`。结果必须与随包校验文件一致。

## 新安装

Windows：运行安装器，选择安装位置，完成后启动。该定制包未使用发布者证书签名；若系统提示来源未知，先核对下载来源和 SHA256，再按公司设备策略处理，不需要关闭全局安全防护。Mac：打开对应芯片的 DMG，将 Meetily 拖入应用程序目录，再从应用程序启动。本次为定制构建，Mac 使用临时签名，不是 Apple Developer ID 公证发行版；系统可能要求在隐私与安全性中确认来源。仅对已核对来源和哈希的应用按系统提示放行，不要关闭整个系统的安全保护。

在首次设置中选择录音保存目录、可用音频输入和系统音频，下载或选择转写模型，再配置纪要模型。转写默认自动识别语言；纪要新安装默认中文，改为自动时跟随会议语言。已有个人设置升级时应保留。使用远程纪要模型会把相关转写文本发给配置的服务，纯本地模型需要另行下载。

Mac 首次使用时授予麦克风、系统音频或屏幕与系统音频录制权限，以系统实际提示为准；授权后若未生效，退出再启动。Windows 检查麦克风隐私设置及选中的输入、输出设备。先手动录一段双方都有说话的测试，回放验证后再启用指定会议号自动录音。

## 升级和回退

先结束录音，等待转写或保存完成，退出包括托盘在内的 Meetily。查明当前应用数据目录、公司数据目录以及配置的录音和模型位置，备份配置文件、`meeting_minutes.sqlite`（若存在则包括同目录 WAL/SHM）、公司模板和相关元数据。不要凭示例路径假定所有电脑目录相同。

安装新版时保留原数据位置。升级后核对会议数量、既有纪要、模型路径、Lark 登录和模板。遇到问题保留日志和新旧备份，不要用空数据库覆盖原记录。回退先备份新版数据，再恢复配套旧程序与兼容数据；不要直接把旧数据库和新库混合。

## 验收顺序

1. 主窗口正常打开，设置返回到原页面，模板编辑关闭正常。
2. 短录音可回放自己和对方的声音，转写不是空白；实时转写启用时离会仍会补齐转写。
3. 生成纪要，核对标题、正文语言、东八区时间、人员名单和表格；没提到的人名或任务负责人不应被猜测。
4. 核对行动项，尝试保存长原文依据的草稿；修改正文不应抹掉独立提取状态或人工草稿。提取失败时纪要仍可保存，界面明确提示重试。
5. 在授权范围内验证测试群回执、自动入会/离会录音、云文档目录和保存链接；每个同事账号独立验收。

本地文件、数据库、权限和真实音频验收分别记录。云端构建成功、签名结构检查或单元测试通过，均不能替代真实 Mac 的双方声音测试。

## 从源码构建（协助安装的 AI 使用）

检出交付包记录的提交，不能只凭版本号。前端位于 `frontend`，Rust 工作区在仓库根目录。使用 Node 20、pnpm 9.15.9、Rust 工具链及各平台编译依赖；以锁文件安装，不随意升级依赖。Windows 需要 Visual Studio C++ 构建工具和 Windows SDK；Mac 需要 Xcode 命令行工具及 CMake。

Windows 先在 frontend 执行 `pnpm install --frozen-lockfile`、`pnpm build`，再构建 Tauri NSIS；使用项目配置中相对的 `frontendDist`，不要把它设为磁盘根目录或不正确的绝对路径。Mac 在本机执行 `bash scripts/build-macos-custom.sh`。辅助程序与主程序使用隔离输出目录；不要把其它架构辅助程序复制进来。完整构建还需访问依赖和受校验的运行库下载地址。

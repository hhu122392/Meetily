# 会议助手现有配置核对记录

核对日期：2026 年 11 月 13 日。按用户要求，以现有国际版 Lark 企业自建“会议助手”的已发布配置为复用基线。本记录不含应用密钥、令牌、实际群号、成员名单或会议内容。

## 一、实际后台核对结果

| 项目 | 结果 |
| --- | --- |
| 应用类型与能力 | 企业自建应用，已启用机器人能力 |
| 状态 | 已启用，当前修改均已发布 |
| 已发布版本 | 1.0.2，审核通过；这是 Lark 应用配置版本，不是 Meetily 客户端版本 |
| 应用身份权限 | 8 项，完整列表见配套权限清单与导入 JSON |
| 用户身份权限 | 7 项，与现有客户端统一 OAuth 请求范围一致 |
| 事件 | 4 项应用身份事件，采用长连接 |
| 重定向地址 | `http://127.0.0.1:18576/lark/callback` |
| 应用可用人员 | 部分成员；新公司需填写自己的范围 |

三个会议事件分别展开后台权限详情，均显示 `vc:meeting.meetingevent:read`、应用身份、已开通。现有应用没有开通应用身份 `vc:meeting:readonly`，后者仅在用户身份下。因此，不能仅凭公开文档就断言现有事件权限配错或必须替换。

## 二、此次文档调整

1. 保留实际可用的应用身份 `vc:meeting.meetingevent:read`，补充公开文档与后台差异说明；新公司按自己后台的事件权限详情确认。
2. 补录现有应用身份 `minutes:minutes.media:export`，导入 JSON 变为应用身份 8 项、用户身份 7 项。明确当前客户端下载使用用户身份，此应用身份项属于现有额外配置，不是当前下载流程必需项。
3. 说明当前授权按钮一次请求全部 7 项用户权限，本机录音模式也不会缩减授权请求。本次没有实现按功能分别授权。
4. 写明 API 预约会议的事件适用范围，以及当前没有群白名单的限制；保留人工确认发群的验收项。
5. 补齐应用创建、机器人能力、凭证、人员范围、发布、入群、连接及授权步骤。申请负责人、保存期限等由新公司填写。
6. 补齐文档包内 Mac 构建说明等相对链接目标。旧压缩包保持原样，新文档单独交付；旧包内说明不应继续作为本次配置基线。

## 三、证据与验证边界

现有应用后台核对覆盖机器人能力、全部权限、四项事件、三个会议事件的权限详情、回调及已发布状态。客户端对照范围包括统一授权入口、OAuth 范围、消息和文件 API、会议预约、状态检测、结束会议与云录音下载。

官方接口文档还要求：用户身份读取录制文件时为会议所有者，且会议已结束、录制已生成。主持人身份、文件访问权与会议所有者不是可以互相替代的条件。

本次没有修改后台、调用结束会议、录制或发消息，没有代替新公司审批，也没有进行真实会议端到端验收。当前用户活跃会议接口及妙记媒体下载接口的完整公开文档本次未取得；现有权限已开通不代表所有新租户接口和套餐一定可用，仍需按配套验收用例实测。

# 云文档独立编辑、预览和保存

本说明替代此前“创建云文档后立即发群”的操作方式。默认不发送群消息。

## 操作

1. 会议纪要工具栏点击“云文档”，默认预览完整 Markdown 正文和表格。点击“编辑正文”修改内容，再切回“预览正文”检查排版。编辑区使用 Markdown 语法，不是嵌入 Lark 原生在线编辑器。
2. “保存草稿”只保存本地 Markdown 文件，并沿用文件版本备份和冲突检查，不需要选择项目或群。
3. 首次选择归档项目；没有项目时填写名称和知识库目录链接。仅有一个项目时自动选中。
4. 点击“创建并保存云文档”，只创建和归档，不发群。以后在同一公司、同一会议、同一项目下点击“保存到云文档”，更新同一篇文档，链接保持不变。
5. 需要发群时，单独点击“发送到群”，选择群、编辑概要、预览后确认。发送操作只附已保存的文档链接，不创建或修改云文档。
6. “打开 Lark 云文档”用于查看云端实际排版。本地预览支持尚未保存的编辑；切换预览不会请求 Lark API。

## 数据和冲突处理

- 完整正文与本地 Markdown 文件共用内容，不会因编辑群消息概要而变化。纪要面板仍与独立 Markdown 文件分别保存。
- 保存云端前先保存本地草稿；上传失败后本地修改仍保留。
- 本地草稿尚未同步时，不能发送云文档链接，避免分享过期内容。
- 云端保存和发群前都会核对文档版本。发现同事在 Lark 修改过文档时停止，不自动覆盖。当前不自动把同事的云端修改合并回本地；请在 Lark 核对和处理，不要直接覆盖。
- 文档更新先插入新正文，再按版本号移除旧正文。如果第二步失败，云端可能同时存在新旧正文；软件会标记保存结果未确认，阻止继续写入和发送，并保留链接供核对。不会自动重试。
- 当前只管理新版编辑流程建立的文档关联；旧版“归档并发送”创建的文档保留在知识库和历史记录中，不自动接管或覆盖。新版首次保存会建立新的可持续编辑文档，此后固定使用该链接。
- 云端文档名称在首次创建时确定，正文中的标题可编辑；此版不自动重命名知识库节点。
- 云端更新以完整正文替换为单位，不提供实时协同、评论同步或任意 Lark 文档导入。图片上传、合并单元格和超过 1000 个转换块的限制与上一版一致。

## 权限

沿用已列出的应用权限：`docx:document.block:convert`、`docx:document`、知识库节点读写、机器人读群及发消息。保存云端不调用读群或发消息接口；只有手动进入发送流程才读取目标群。应用还须具有目标知识库和文档访问权。

官方接口依据：[创建嵌套块](https://open.larksuite.com/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document-block-descendant/create.md)、[批量删除子块](https://open.larksuite.com/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document-block-children/batch_delete.md)、[获取文档信息](https://open.larksuite.com/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document/get.md)。

## 验收边界

本地自动测试检查默认不发送、编辑预览、草稿保留、版本冲突、先写后删、异常中止、关联唯一性及独立发送流程。真实 Lark 权限、创建、二次更新链接不变和群内打开效果仍需使用安装后的应用验收。构建成功不等于真实云端验收通过。

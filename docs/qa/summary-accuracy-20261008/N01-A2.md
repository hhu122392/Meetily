# N01-A2: preserve configured desktop diagnostics

2026-10-08. Scope passed: native desktop logging configuration. Summary generation and accuracy remain unaccepted.

`main.rs` overwrote RUST_LOG with info; `lib.rs::run` then clamped the global maximum to Info. Changing only the main entry in v6 did not expose sidecar debug logs. That failed attempt was stopped through the owned QA client's actual stop button; managed helper processes reached zero and the previous body/source/generation stayed unchanged.

The fix uses env_logger's default info filter while respecting configured filters, and removes the second clamp. It changes two startup statements, adds no log payload, and leaves model parameters, grammar, token budgets and timeouts unchanged.

The identical v7 EXE was started twice in the actual Windows desktop client. With RUST_LOG absent, startup/setup emitted INFO and the Tauri client opened normally. With `info,app_lib::summary::summary_engine::sidecar=debug`, an actual native history-template generation exposed DEBUG helper records, including CPU model buffers and a tokenized 5661-token prompt. This demonstrates configuration propagation; it does not explain or resolve the entire timeout.

Native process/window identity, executable fingerprint, owned CDP target and before/after foreground samples were checked. No OS input or window activation was sent. The QA build used focus=false/focusable=false; this is not a release installer validation. Summary core edits were present in the tested candidate but remain uncommitted/unaccepted; this commit contains only logging startup changes and this sanitized record.

Evidence: `N01-A2-native-metadata.json`. Raw native transcripts, full helper logs, API credentials and database backup remain local. The model generation was still running when this diagnostic slice was accepted; no summary success or accuracy result is claimed.

# Lark 与 Meetily 配置及变更说明

文档日期：2026 年 11 月 7 日。适用于将 Meetily 中文定制版部署到另一家公司，也适用于已有会议助手升级到包含模板管理、文字纠错及逐段编辑的版本。

权限明细见 [Lark 权限申请清单](./Lark权限申请清单.md)。本说明只记录需要配置的项目，不包含任何公司的真实 App Secret、登录令牌、群 ID 或会议内容。

## 一、本次升级需要修改什么

| 项目 | 新公司首次使用 | 已接入公司的本次升级 |
| --- | --- | --- |
| 企业自建应用与机器人 | 在本公司创建并启用机器人 | 沿用已有应用 |
| App ID／App Secret | 使用新公司自己的凭证 | 未轮换密钥时无需更换 |
| 应用／用户权限 | 按完整清单申请 | 已齐全则无需新增；缺项需补申请并生效 |
| 长连接与四项事件 | 按本文配置 | 核对已有配置，不能改成不支持的事件类型 |
| OAuth 重定向地址 | 添加固定本机回调 | Windows、Mac 地址相同，无需因换操作系统改地址 |
| 应用可用范围和目标群 | 发布后把机器人加入本公司的群 | 群或人员发生变化时更新范围及成员 |
| Meetily 公司资料 | 新建本公司资料，再配置应用 | 保留已有公司资料和会议数据 |
| Windows → Mac 授权 | Mac 上重新填凭证并授权 | Windows 加密凭证不能直接复制到 Mac 使用 |
| 纪要模板与纠错 | 在 Meetily 配置 | 本次新增功能本身不需要新的 Lark 权限 |
| 同账号多台电脑 | 指定一个在线处理实例 | 退出另一台 Meetily，或关闭其企业应用连接 |

已有应用如果已具备全部权限和事件，升级主要是安装新版本及检查 Meetily 设置，不需要重新创建应用。申请新的权限后，必须按平台要求使其生效，并在 Meetily 重新授权。

## 二、Lark 后台按顺序配置

### 1. 创建应用和确定负责人

用目标公司的账号打开 [Lark 开发者后台](https://open.larksuite.com/app)，核对组织名称，创建企业自建应用“会议助手”，填写本公司的用途说明和负责人。添加“机器人”能力。

本项目使用国际版 `open.larksuite.com`，不是国内飞书 `open.feishu.cn`；当前客户端未提供两种域名的切换选项。如果新公司使用国内飞书，需要另行适配并验收。

### 2. 配置权限

在“权限管理”分别申请应用身份和用户身份权限，完整列表见 [权限申请文档](./Lark权限申请清单.md)。可使用 [权限导入 JSON](./lark-permissions-import.json) 辅助填写，但导入不等于权限已经生效。

如公司只批准最小本机录音权限，应先由维护人员调整当前统一授权按钮的申请范围；不能直接删减清单后承诺现有版本正常授权。

### 3. 添加本机授权回调

“安全设置 → 重定向 URL”添加：

```text
http://127.0.0.1:18576/lark/callback
```

该地址用于当前电脑的浏览器完成 OAuth。无需把端口暴露到公网，也不需要为此修改组织防火墙或 IP 白名单策略。授权操作应在运行 Meetily 的同一台电脑完成。

### 4. 先连接客户端，再保存长连接

在 Meetily 中切换或新建正确的公司资料，进入“设置 → Lark 机器人 → 企业应用”，填写对应应用的 App ID／App Secret，开启“启用企业应用连接”，点击“保存并连接”。

保持客户端运行，在 Lark 后台的“事件与回调 → 事件配置”选择“使用长连接接收事件”，保存并添加下列四项应用身份事件：

```text
im.message.receive_v1
vc.meeting.join_meeting_v1
vc.meeting.leave_meeting_v1
vc.meeting.meeting_ended_v1
```

如后台提示需客户端在线，先检查 Meetily 的连接状态、应用凭证和网络，再保存长连接配置。不要把 OAuth 回调 URL 填进事件接收地址。该配置顺序可参考[开放平台的长连接设置步骤](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)。

### 5. 发布并加入目标群

在“版本管理与发布”创建版本，填写发布说明与实际可用人员范围，按本公司的流程审批或发布，确认配置已生效。可使用以下发布说明：

> 新增企业内部会议助手，支持群内指令创建与关联会议、本人授权后的会议控制和录音获取。录音交由 Meetily 转写并按模板生成纪要，经人工预览确认后发送概要及可选 Markdown 附件。

发布后，由有权限的人员把本公司的机器人添加到目标测试群。搜不到应用时，依次检查组织、发布状态、可用人员范围和群管理限制。

### 6. 用户授权

回到 Meetily 点击“授权会议助手”，在浏览器选择负责处理会议的同公司账号，完成授权。返回客户端检查授权状态和连接状态。

更换授权账号、补充用户权限或从 Windows 换到 Mac 后，需要重新授权。不要把已有数据库中的凭证字段或令牌拷贝给新公司。

## 三、Meetily 需要配置的内容

| 页面／项目 | 操作与效果 |
| --- | --- |
| 公司资料 | 确认当前公司，再填写应用配置；每家公司用自己的应用和账号 |
| 转写模型 | 下载并选好可用模型；Mac M 系列可使用匹配安装包中的本地引擎 |
| 纪要模型 | 选择本地模型或公司批准的远程模型服务，检查连接可用 |
| 录音目录 | 指定有写入权限、空间足够的目录，制定备份与保存期限 |
| 自动录音 | 按需开启“加入会议助手新建的会议时自动录音”；对后续新会议生效 |
| 录音来源 | 云录音下载 Lark 录制文件；本机录音采集该电脑的麦克风和系统声音 |
| 准备发群 | 开启后为新会议准备目标群关联，仍需人工审核确认发送 |
| 其他群成员开会 | 按需开启允许群成员发起；处理仍使用本机授权账号，不是每人独立授权 |
| 纪要模板 | 在模板库管理默认模板，或在会议中选模板；重新生成时按章节及要求输出 |
| 会议背景与人员 | 按会议填写主持人、参会人员及背景，供生成和纠错参考 |
| 转写文字纠错 | 转写区域“优化转写 → 转写文字纠错”；规则预览后可手动请求 AI 校对 |
| 逐段手动编辑 | 鼠标移到段落，点击右侧铅笔；保存前备份，已有纪要需重新生成 |
| Lark 发送 | 纪要右上角“编辑 Lark 消息／发送到 Lark”，核对目标群和预览后确认 |

云录音必须满足账号、会议及套餐条件。当前实现要求授权账号入会且为主持人，才能自动请求开始录制；机器人不会作为独立参会人自己进入会议收音。本机录音模式必须在实际参会并播放会议声音的电脑上运行。

## 四、多设备与 Mac 说明

同一 App ID／授权账号没有主备设备认领机制。当前版本中的事件去重、任务状态和会议关联保存在每台电脑本地，不会自动同步到另一台。

常用方式是：两台电脑都可以登录 Lark，但只在主要记录电脑运行已连接该应用的 Meetily。另一台完全退出 Meetily，或关闭“启用企业应用连接”。关闭窗口是否退出应以进程／后台状态为准；切换电脑前先结束录音并确认后台任务状态。

本次 Mac 安装包面向 Apple Silicon（M 系列），要求 macOS 14.4 或以上；Intel Mac 需另用 Intel 构建。Mac 首次本机录音按系统提示允许麦克风、系统音频或屏幕录制。云录音无需本机收音，但需要网络和目录写入权限。

Mac 凭证密钥保存在登录钥匙串；Windows 凭证与 Windows 用户绑定。两端不能直接共用加密凭证，Mac 应重新配置应用并授权。安装和构建边界见 [Mac 构建说明](./MACOS_CUSTOM_BUILD_ZH.md)。

## 五、验收用例

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1 | 本人到测试群，真正 @机器人并发送“开会 配置验收” | 同群返回会议链接，目标群正确 |
| 2 | 授权本人加入会议，按来源满足主持人或本机收音条件 | Meetily 出现对应会议录音状态 |
| 3 | 讲一段无敏感内容的测试文字 | 本机产生录音，或 Lark 显示云录制 |
| 4 | 主持人结束整场会议；也可在满足权限时使用“@会议助手 结束会议” | 云录音等待文件后下载，本机录音按会议状态停止 |
| 5 | 等待后台处理完成 | 转写可读，按所选模板生成纪要 |
| 6 | 手动改一处测试转写，保存，再重新生成纪要 | 转写修改保留，生成使用更新后的内容；原纪要不会在保存转写时自动改写 |
| 7 | 打开文字纠错预览；需要时选择 AI 校对 | 先给候选，勾选确认后才应用；可查看备份差异 |
| 8 | 编辑并预览 Lark 消息，确认目标群和附件后发送 | 原群收到所确认的概要和选定附件 |
| 9 | 重启 Meetily，再查看会议和授权状态 | 历史会议可读，凭证可正常读取或显示明确的重新授权提示 |

验收中的发群操作由实际部署人员确认执行。本次文档生成和云端打包没有代替新公司的权限审批，也没有自动发出任何 Lark 消息。

## 六、故障与对应修改项

| 现象 | 检查／修改 |
| --- | --- |
| 开会指令没有响应 | 实际 @、机器人已进群、应用已发布、人员范围、接收消息事件、允许发起的用户范围、主要电脑在线 |
| 两台电脑行为不一致 | 同应用只留一个在线处理实例；本地去重不能解决跨设备协调 |
| 授权失败／回调不匹配 | 完整回调 URL、公司账号、用户身份权限、发布生效状态；新增权限后补授权 |
| 无法保存长连接 | 先在 Meetily 保存并建立连接；检查凭证和网络 |
| 能录音但云文件无法下载 | 用户身份的录制读取、会议信息及音视频下载权限；文件归属、分享或下载限制 |
| 云录制启动失败 | 授权本人是否在会中且为主持人；租户套餐、管理员录制策略和权限 |
| 结束会议失败 | 是否属于当前群创建的会议、请求人身份、授权账号主持人状态及 `vc:meeting` 权限 |
| 改了转写，纪要没变化 | 保存转写不会改写纪要；确认模板后重新生成 |
| 消息卡片可发，Markdown 附件失败 | `im:resource`、文件写入状态、附件选择及目标群 |
| API 额度或限流报错 | 查看错误码与平台用量，避免反复点击重试；记录时间和请求标识供管理员排查 |
| Mac 找不到旧授权 | Windows 凭证不可直接解密；在 Mac 当前公司资料中重新填凭证并授权 |

## 七、需要交给新公司的材料

交付该批次安装包、两份配置文档、权限导入 JSON、权限与事件核对清单、Mac 安装说明和代码版本号。App ID／App Secret 由新公司自行创建并按安全流程交付，不随公开 Git 仓库或安装包提供。新公司的群、用户授权和会议数据也不随本次发布迁移。

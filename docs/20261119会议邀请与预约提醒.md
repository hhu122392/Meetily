# 会议邀请、预约提醒和本地录音

## 使用方法

1. 在设置的「Lark 会议助手」选择「群指令开会 · 自动关联」，录音来源选择本机录音，开启自动录音，保存并连接。
2. 应用后台需有用户身份 `calendar:calendar.event:read` 权限；发布后点击「授权会议助手」重新授权一次。直接视频会议邀请的解析不调用日历接口，日程邀请需要读取日程权限。
3. 在目标群真正 @会议助手，粘贴 Lark 复制出来的完整邀请。以下两种格式均可识别：
   - 「邀请你加入 Lark 视频会议」：主题、时间、GMT 时区、会议 ID、入会链接。
   - 「加入 Lark 日程」：分享链接、日程主题、具体日期和起止时间。请分享周期会议的「此日程」。
4. 在设置中的「会议预约与提醒」查看是否核对成功。失败时显示原因，可重试或取消。
5. 开始时间到达后，机器人向原群发送会议号和入会链接。本人用授权账号进入对应会议后，Meetily 自动本地录音；离会停止，补齐转写后生成纪要。纪要发送仍按原审核流程操作。

如果让同事发邀请，在主要录音电脑上开启「允许群成员 @会议助手 开会或提交会议邀请」。默认关闭，仍只接受授权本人。纯会议号绑定仍限本人。

## 日程邀请的边界

日程分享链接没有直接包含会议号。本版使用授权账号主日历中的具体实例定位候选，再通过日程分享信息接口核对分享 token；不会仅凭标题和时间猜测。须先通过 Lark 打开邀请、加入该日程，使其出现在授权账号的主日历。

如果没有权限、链接失效、找不到具体实例、分享 token 不能唯一对应，或日程没有 Lark 视频会议链接，会显示失败原因，停止提醒与自动录音绑定。此时可改发带会议号的完整视频会议邀请。暂不支持只有日程链接而没有主题和时间的文本，也不会自动展开「所有日程」产生无限期提醒。

日程在接收、会前半小时和开始前会重新核对；接口返回改期时采用新时间，取消或无法访问时停止处理。只发视频会议邀请时，以群里收到的文本为准，改期请重新发送。

## 重复、改期与重启

- 同群、同日、同会议号的视频邀请重复发送，更新尚未发送的预约；跨天视为下一次会议。同日同会议号举办多场会议，请分群或使用各次日程邀请。
- 同日程分享 token 的新邀请更新尚未发送的预约；旧消息或重复投递不会覆盖新状态。
- 同群两种邀请核对为同一会议号、同一开始时间时只发一次。已发送或送达不确定的提醒不会因为重发邀请而再次自动发送。
- 会前半小时才启用预约的录音绑定；单独发送会议号或入会链接仍走原本六小时绑定规则。
- 待办持久化到本地，重启后继续处理。电脑必须开机联网、Meetily 持续运行；睡眠和关机期间无法提醒或录音。开始后十分钟以内恢复可补发，超过十分钟不补发。
- 发送中断会标为「送达待核对」，不会自动重发；明确失败可手动重试。取消预约撤销其尚未开始的录音绑定，不中止已经进行的录音。
- 关闭群指令模式或停用助手后不发送预约提醒；自动录音需在提交邀请前开启。多个群绑定同一场会议时沿用原有保护，暂停自动录音。
- 同一应用只配置一台主要电脑接收群指令。Lark 长连接为集群投递，多台同时接收可能分走消息，本版未实现跨电脑共享预约队列。

## 接口与权限

- 接收群 @消息：`im:message.group_at_msg:readonly`。
- 机器人发送提醒：`im:message:send_as_bot`。
- 日程读取及分享信息：用户身份 `calendar:calendar.event:read`。
- 当前会议识别与入离会事件：沿用已配置的 `vc:meeting.meetingevent:read` 及会议控制授权。
- 不申请云录音权限，不启动云录音，不自动加入日程或进入会议。

接口依据：[Lark 官方 SDK 日历接口](https://github.com/larksuite/oapi-sdk-go/blob/v3_main/service/calendar/v4/resource.go)、[Lark 官方 CLI 日历接口目录](https://github.com/larksuite/cli/blob/main/internal/registry/catalog/services/calendar.json)。日程 `share_info` 使用 POST 获取分享信息，返回 `share_link`，属于读取操作。

## 验证边界

自动化测试使用模拟接口和内存数据库，不会向真实群发送测试消息或启动麦克风。验证解析、接收者限制、去重、预约持久化、到点发送、取消、过期、异常发送及原自动录音逻辑。

开发时读取当前本机状态：处于手动模式、自动录音关闭，用户令牌已过期；只读日历请求返回 HTTP 401。未替用户改变模式、刷新凭据、加入日程或发送群消息。完整真实链路仍需升级后重新授权，并在测试群以未来时间的会议验收。
